# Exhaustive Canonical Skeletons Generation

Neural symbolic regression (SR) benefits from diverse training expressions, but datasets built with stochastic sampling can contain many structurally redundant expressions and leave parts of the function space underrepresented. This project introduces an exhaustive dataset of univariate canonical skeletons generated by a deterministic, constrained context-free grammar. Each skeleton represents a family of more specific functions, reducing repeated structures while supporting decomposable SR on multivariate problems without assuming linear separability. The project also provides a sampling pipeline designed to produce clean numerical data without protected operators. Canonicalized comparisons with existing neural SR datasets show a more compact collection, no repeated structures, and a more uniform operator distribution.

## Installation

The generation entry point requires Python and the following packages:

```bash
pip install pandas pyarrow sympy
```

Run the exhaustive skeleton generator from the repository root:

```bash
python main.py
```

## Project Structure

| Path | Purpose |
| --- | --- |
| `main.py` | Builds the configured grammar, runs exhaustive generation, and writes the canonical skeleton dataset. |
| `config.py` | Defines grammar limits, unary operators, output path, and numerical sampling settings. |
| `src/grammar/cfg.py` | Defines the structural context-free grammar and its production rules. |
| `src/grammar/engine.py` | Implements derivation-tree nodes, grammar expansion, and rule constraints. |
| `src/pipeline.py` | `generate_exhaustive_skeletons()` explores valid derivations, simplifies and canonicalizes completed expressions, and returns unique skeletons. |
| `src/symbolic/reducer.py` | Simplifies expressions and removes algebraic redundancies, including inverse operations. |
| `src/symbolic/normalizer.py` | Sorts commutative expression terms into a canonical representation. |
| `src/symbolic/canonicalizer.py` | Maps concrete expressions into abstract canonical forms. |
| `src/sampler/sample.py` | Samples constants and input points, evaluates skeletons, and creates numerical datasets. |
| `src/sampler/generate_datasets.py` | Batches skeletons and generates or curates sampled datasets. |
| `src/sampler/generate_extrapolation_datasets.py` | Generates evaluation data outside the training support. |
| `src/data/` | Contains the canonical skeleton dataset and derived difficulty, interpolation, extrapolation, and curated Parquet datasets, plus table and plotting scripts. |
| `src/utils/` | Shared constraint checks, skeleton helpers, and SymPy utilities. |
| `src/other_datasets/` | Comparison resources for other symbolic-regression datasets. |

## Generate Canonical Skeletons

The command `python main.py` calls `main()`. That function reads its settings from `config.py`, constructs a `StructuralGrammar`, and passes the grammar and limits to `generate_exhaustive_skeletons()`:

```python
from src.grammar.cfg import StructuralGrammar
from src.pipeline import generate_exhaustive_skeletons
import config

grammar = StructuralGrammar(unary_operators=config.UNARY_OPERATORS)
skeletons = generate_exhaustive_skeletons(
    grammar=grammar,
    n_u=config.N_U,
    n_d=config.N_D,
    unary_ops=config.UNARY_OPERATORS,
)
```

Parameters:

- `grammar`: The `StructuralGrammar` instance defining the start symbol, terminals, and production rules.
- `n_u`: Maximum total number of unary operators allowed in a skeleton. Configured by `config.N_U`.
- `n_d`: Maximum nesting depth of unary operators. Configured by `config.N_D`.
- `unary_ops`: Unary operator names available to the grammar and used when counting unary-operator constraints. Configured by `config.UNARY_OPERATORS`.

The function returns a set of unique canonical skeleton strings. `main()` stores them in `src/data/canonical_skeletons.parquet` using Snappy compression.

## Dataset

The main canonical skeleton table is [`src/data/canonical_skeletons.parquet`](src/data/canonical_skeletons.parquet). Related files, including the original and easy, medium, and hard skeleton subsets, are in the same directory.

The main table has one row per canonical skeleton and the following columns:

| Column | Description |
| --- | --- |
| `skeleton` | Canonical symbolic expression stored as a string. `C`, `L`, and `P` are abstract placeholders for constant, linear, and higher-degree polynomial components; unary functions come from the configured operator set. |
| `skeleton_length` | Number of characters in the skeleton string; used when ordering and dividing skeletons by complexity. |

The data-generation scripts also produce sampled datasets with columns such as `equation`, `X`, and `Y`; these contain sampled concrete expressions and their input/output values and are distinct from the canonical skeleton table.
